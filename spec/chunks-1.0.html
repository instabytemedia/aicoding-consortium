Chunk Addressing 1.0

Stable, hash-verifiable addresses for parts of documents — cite a paragraph, fetch a section, verify a quote.

Status of This Document

This is an Editor's Draft. It has no standing and will change. It is published so that origins, engines, and adjacent standards bodies can shape it before it hardens. Comments via the public repository.

Abstract

Agents quote the web constantly but can address almost none of it: fragments break on redesign, quotes cannot be re-verified, and fetching one section means fetching the document. This report promotes the chunk model seeded in AIX § 4 to a full layer: an identifier grammar, stability obligations, a reproducible per-chunk hash, and the citation form url#id@hash that makes any quote re-checkable forever.

1. Identifier Grammar & Stability

A chunk id MUST match ^[a-z0-9][a-z0-9-]{0,63}$ and be unique per resource. For HTML it is an element id; for markdown, the heading slug computed by this normative algorithm: (1) Unicode-normalise to NFKD and drop non-ASCII code points, (2) lowercase, (3) replace each whitespace run with one hyphen, (4) delete characters outside [a-z0-9-], (5) collapse hyphen runs, trim leading/trailing hyphens, (6) truncate to 64 characters, (7) on duplicates within a resource, suffix -2, -3, … in document order. An id MUST remain attached to its topic across revisions and MUST NOT be reused for different content once retired — the AICC Core § 6.2 rule, applied to content.

2. Citation Form

A full citation is <url>#<id>@<hash-prefix>, where the hash prefix is at least 12 hex chars of the chunk's AIX § 3.1 hash. Engines SHOULD emit full citations when quoting; a consumer re-fetches the chunk, recomputes the hash, and knows whether the quoted text still exists, changed, or vanished. The bare form url#id remains a valid browser link — humans and agents share one address.

3. Security Considerations

  • Quote integrity. Hash-pinned citations detect silent revision of quoted material — and equally protect origins against misquotation.
  • Id squatting. Reusing a retired id for different content is the content-level variant of requirement-id reuse; validators flag it across AIX snapshots.
