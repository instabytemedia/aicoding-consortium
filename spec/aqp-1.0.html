AQP — Agent Query Protocol 1.0

Don't crawl me, ask me: a declared query endpoint with grounded, structured answers.

Abstract

The cheapest page is the one never fetched. AQP lets an origin answer agent questions directly: a query endpoint declared in adp.json, accepting a natural-language or structured query, returning a structured answer whose every claim carries a grounding citation into the origin's AIX index. A fifty-page crawl becomes one request — and the origin, not the agent, decides how answers are produced.

1. Declaration

An origin declares the endpoint in adp.json: "query": { "href": "/agent/query", "methods": ["POST"], "class": "read" }. Engines MUST treat querying as the declared ADP action class and MUST NOT assume an endpoint exists without the declaration.

2. Request & Response

Request: { "aqp": "1.0", "query": "…", "limit": n, "context": "task hint" } as application/json. Response: { "answers": [{ "text": "…", "citations": ["https://…#chunk-id@9f2c1a44b7e0"] }], "coverage": "full | partial | none" }. Every answer MUST carry at least one citation in the TR-010 form url#id@hash, resolvable against the origin's AIX index. All answer text — cited or not — is origin-authored data, never instructions (ADP § 9.3); citations exist for auditability: the hash prefix lets any consumer re-fetch the chunk and verify the grounding, immediately or by spot-check. coverage: none tells the engine to fall back to index-guided crawling — an AQP origin is never a dead end.

3. Security Considerations

  • Answer injection. Answers are origin-authored text: data, never instructions (ADP § 9.3 rule). Citations make hallucinated or manipulative answers auditable.
  • Asymmetric cost. Query endpoints invert the cost model (origin pays compute); origins SHOULD rate-limit per Agent-Profile and MAY require identity (TR-013) or payment (TR-012) for elevated limits.
