Abstract

ADP's Agent-Profile header is a claim anyone can type. This report makes it verifiable: an Agent-Attestation header carrying a short-lived token signed by the engine vendor, binding the request to a registered engine and a principal class (interactive-user | scheduled | autonomous-service) — deliberately never the principal's identity. Origins can then grant real trust tiers (TR-012) to verified engines while treating unverifiable traffic as anonymous, and a misbehaving engine's attestation is revocable at the registry.

1. Mechanism

Agent-Attestation is a compact signed token (issuer = engine vendor key published in the AICC Engine Registry entry; audience = target origin; expiry ≤ 10 minutes; claims: engine id, ADP level, principal class). Origins verify against registry keys with standard caching. Engines MUST NOT include user-identifying data in attestations — the privacy rule of ADP § 8 is load-bearing here. Verification failure downgrades trust; it MUST NOT block the free tier.

2. Security Considerations

  • Token replay. Short expiry + audience binding; origins MAY add nonce challenges for execute-class requests.
  • Registry as trust root. The registry publishes keys, never issues them; vendors control their own keys and revocation. Governance keeps the registry non-discriminatory (reverse-DNS engines can self-publish keys at their own well-known location).
  • Anonymity preserved. Attestation classes traffic, it does not identify humans; origins requiring more must use their own auth (ADP handoff).
