About the Consortium

What this is, in plain language.

Software is increasingly written and operated by AI agents — tools like Claude Code that read your project, follow your rules, and do work on your behalf. Soon those agents will also be the web's biggest readers: fetching documentation, comparing products, filing issues, completing transactions. The AI Coding Consortium exists to give that world rules — open, free, owned by no vendor. Think of it as what the W3C was for the browser web, built for the agent web.

The three problems we solve

1. Every AI tool speaks its own dialect

Teams write the same instructions five times — a CLAUDE.md for one tool, an AGENTS.md for another, .cursorrules for a third. The copies drift apart and none of them can be checked for correctness. Our answer is AICC Markdown: one file format that every tool can read, precise enough that a validator can prove it's well-formed — the way HTML has one standard instead of one per browser.

2. Agents read the web blindly — and wastefully

When an AI agent researches a website today, it downloads whole pages full of menus and trackers to find a paragraph of content, and re-reads everything on every visit because nothing tells it what changed. That waste has a price tag (AI reading is metered in "tokens"). Our answer is a set of small, boring files a site publishes — agents.txt says what agents may do, an index says what each page contains and whether it changed. Like robots.txt and sitemaps in the 2000s: one text file, massive effect.

3. Nobody agreed on the rules of engagement

May an agent submit a form on your site? Quote your content? Pay for access? Prove who sent it? Today these questions are settled by blocking bots and hoping. The Agent Web Stack drafts answer each one explicitly — permission levels, provenance, payment negotiation, agent identity, content licensing signals.

Why should you care?

If you run a website: agents that can read you cheaply will find, quote, and recommend you; agents that can't will skip you. Being agent-readable is becoming what being Google-indexable was in 2005. Scan your site — most fixes are a single text file.

If you build software with AI tools: one validated spec file replaces your zoo of instruction files, and features like context-exclude measurably cut what your AI tool reads — which is time and money on every session. There's a Claude Code plugin that migrates your existing files in one command.

If you make an AI engine: the standards are vendor-neutral, royalty-free, and come with conformance tests. Adopting them means every AICC-ready site on the internet just became cheaper for your engine to use.

Who is behind this — honestly

This is a young initiative, and we label everything by maturity: one standard is feature- frozen (Candidate Recommendation), one is a stable Working Draft, and the frontier layers are Editor's Drafts — published early precisely so they can be challenged. Everything is open source (specs CC-BY-4.0, code MIT, a royalty-free patent policy), every claim is one click from proof (validators, conformance suite, live scanner), and this very website implements every standard it publishes — it is the first origin to score grade A in its own scanner. What we need next is what every standard needs: adopters, critics, and a second independent implementation. That could be you.

In one sentence

We write the boring text files that make the AI-driven internet work — open, verifiable, and owned by everyone.
